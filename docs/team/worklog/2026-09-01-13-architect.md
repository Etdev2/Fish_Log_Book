## 33 — 2026-09-03 — The vector tripwire polices again, and the maths it now checks

Entry 32 left this as "needs a decision". Decision taken and implemented.

- **The bug.** `check-tripwires.mjs` rule 3 did `readdirSync("src/core/rules")` and kept
  the `.ts` files. Once the rules grew subdirectories that top level held only `astro/`,
  `catch/`, `tide/`, `vectors/` — zero `.ts` matches — so ADR 003 §4's "every rule has a
  test vector" guard had been enforcing NOTHING, and its clean result was the symptom.
- **The convention**, which had to be settled before the tripwire could be honest: a
  vector file now declares a `covers` array naming the modules it polices. That is what
  makes `astro.json` legitimately covering three modules distinguishable from a gap, and
  it is backward-compatible with both files that already existed. A module needs a vector
  when it has an `export function`; type-only files, `constants.ts` and barrels are exempt
  by rule instead of by being silently skipped. The tripwire also fails on a `covers` entry
  pointing at a module that no longer exists, so a vector cannot rot into a no-op.
- It now polices **12 modules, up from 0**. Both failure modes are proven: an uncovered new
  module fails, and a stale `covers` fails.
- **The vectors that were missing.** 6 new files, ~50 cases. Every expected value was
  derived in a separate implementation and none by running the TypeScript it checks — the
  discipline `astro.json` set out and the only thing that makes a vector worth having:
  - `catch-measurement.json` — the exact defined SI factors (1959 yard-and-pound; NIST
    SP 811). **Found a real defect doing it:** `inHgToHpa` used 33.8639 where NIST defines
    3386.389 Pa (33.86389 hPa), and `knotsToMps` used 0.514444 where the 1852 m nautical
    mile gives 1852/3600. Both were truncations, and both sat in a file whose every other
    factor is exact and whose header promises values "stored SI-canonical so a Hawaii
    pressure and a North-Sea pressure mean the same number". Now named constants with the
    exact values; ~0.0003 hPa at a typical 29.92 inHg, invisible on the glass but wrong in
    the stored number that syncs and will feed correlation later.
  - `tide-height.json` — Fritsch & Carlson (1980) reimplemented from the paper's tangent
    construction, over REAL NOAA CO-OPS predictions for station 9410580. At a sample
    instant the expected height is NOAA's own published number, so `heightAt` is checked
    against NOAA rather than against us. Our implementation agrees to 1e-9. Also pins
    Fritsch-Carlson's own no-overshoot guarantee, which is what stops the curve inventing
    a water level NOAA never predicted.
  - `tide-turns.json` (NOAA published H/L marks; slack windows as estimates, never
    `published`), `tide-pace.json` (fixed-interval percentile ranking), `tide-state.json`
    (motion thresholds, rule of twelfths, `dailyRange` certainty on both paths),
    `catch-search.json` (AND-of-tokens matching, every filter dimension, the UUIDv7
    tie-break, newest-day-first grouping).
- Two of my own errors caught by the vectors rather than by me: `paceAt` takes the rate as
  an argument (and never reads its `at` parameter — worth a look someday), and `dailyRange`
  certainty is `published` only when both extremes landed on published marks, which an
  endpoint sitting exactly on a sample also satisfies.
- **ADR numbering.** Two ADRs were both numbered 007. `007-regional-expansion-and-catch-gps`
  landed first and keeps the number; the regulations/geospatial ADR moves to 008. Every
  numbered "ADR 007 §N" citation in the repo refers to the regional-expansion ADR — the
  regulations ADR has never had numbered sections — so only two bare citations and two file
  paths needed changing, all verified individually rather than swept.
