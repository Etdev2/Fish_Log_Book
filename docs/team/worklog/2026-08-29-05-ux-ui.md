### 2026-08-29 | ux-ui | 2h 10m

Six rapid founder-feedback rounds, addressed in the order the coordinator queued them.
`npm run verify` green after each. Dev server still running at
**http://localhost:3413/tides**.

**1. Disclosure marker colour.** `text-text-muted` read as inert; switched to
`text-text-link` (the token the shell nav already uses for "non-primary tappable text",
per `01-foundations.md`'s own description) plus an explicit chevron, since colour alone
isn't a reliable "this opens" signal. Measured: text-link on the status-cell `surface`
background is 11.35:1 (AAA), per the foundations table. One theme only in this app, so
there is no separate light-mode number to check.

**2. Local time zone by default.** New `use-local-time-zone.ts` resolves the viewer's
IANA zone via `Intl.DateTimeFormat().resolvedOptions().timeZone`, on the same
`useSyncExternalStore` discipline `useNow()` uses — `getServerSnapshot` returns `null`,
so server and first-client-render markup are identical (the station's own zone as
fallback), and the real zone swaps in after hydration. Every clock/day label on screen
now uses it, with a zone abbreviation always shown, and one quiet sentence if the
viewer's zone differs from the station's — not on every timestamp. The astro calls
(`daylightSpans`/`sunEventsFor`) still key off the station's real location, correctly.
Known simplification: the day-boundary/midnight-gridline math in
`tide-chart-geometry.ts` is still anchored to the station's fixed UTC-7 offset, not
re-derived per viewer zone — a cosmetic imprecision (gridlines land near, not exactly
at, the viewer's real local midnight), not a factual error in any displayed timestamp.

**3. Real NOAA data spanning today.** `tide-fixture.ts` is now a real fetch from NOAA
CO-OPS's public `datagetter` API for station 9410580 — `interval=h` merged with
`interval=hilo`, `time_zone=gmt`, `units=metric`, `datum=MLLW` — covering **2026-08-27
00:00 UTC through 2026-09-04 23:00 UTC**, retrieved **2026-08-30T02:39:05Z**
(`TIDE_RETRIEVED_AT_UTC`, real recorded provenance, unlike the old fixture's "not
recorded"). Nothing synthesised — 248 real points. Verified in the running app: the
default selected point lands at "Saturday, August 29, 7:39pm" (chosen at fetch time to
sit near "now"), which is inside the loaded window, so the live NOW marker and the
current tide readout both populate instead of sitting empty. The "Cached fixture — not
a live reading" badge stays; this is a snapshot, not a live feed.

**4. Day/night shading contrast.** The previous shading measured (self-contrast) at
only 1.19:1 between night and day backgrounds — effectively invisible, confirming the
founder's complaint. New treatment: day is a warm `moon-pale` tint at 12% opacity,
night is `background` at 90% opacity, and civil twilight is a real `linearGradient`
between the two per span (direction-aware: dawn goes night-color -> day-color,
dusk the reverse) rather than a third flat colour. This is a genuine trade-off on a
single dark theme (no separate light mode to treat differently — tokens.json's
`$darkOnlyByDesign`): a visibly lighter day band necessarily narrows contrast against
light foreground text. **Worst ratio measured: text-muted on the new day band, 4.88:1**
— clears WCAG AA (4.5:1) comfortably, sits under this app's stricter 7:1 target and
under the one already-documented 6.48:1 exception (both scoped to plain `surface`, a
different pairing). Every other foreground I checked (text-primary, tide-cyan,
amber-flag, signal-orange) stays at 6:1 or higher on both bands. I did not edit
`06-accessibility-baseline.md` (out of my write scope for this branch) — flagging this
new pairing for whoever owns that doc to bless or push back on.

**5. Sunrise/sunset on the curve.** Moved from off-curve ticks to markers anchored at
the engine's actual height at that instant (`heightAt`, same treatment as the H/L turn
dots) — a small sun glyph (circle + 6 short rays, amber-flag) rather than another
coloured circle, so it's visually distinct from the cyan H/L dots, the orange SELECTED
read-head, and the muted NOW marker. Collision handling: when a sunrise/sunset label
would land within 40px of a turn label, the text is suppressed and the marker gets an
`aria-label` instead — the accessible name never disappears, only the printed text.
`aria-valuetext` on the scroller now also says "in darkness" / "near dawn or dusk" when
the selected point falls there — confirmed in the rendered HTML.

**6. Chart-first layout.** The chart card now renders before the status grid — DOM
order, not just CSS order, so tab order and screen-reader order follow the new visual
order without a separate fix. The header above the chart is cut down to the station
line, moon phase, and the "Tide" h1 only; the descriptive paragraphs (predicted-height
blurb, time-zone note, sun/moon note, "Cached fixture" badge, live-clock note) moved
below the status grid rather than being dropped. Confirmed in the rendered HTML that H1
-> slider -> `<dl>` is now the actual document order. Because the grid can now sit off
one screen's height below the chart on a phone, the floating drag-readout pill (already
always visible above the curve, not just mid-drag) now also shows motion state
(Rising/Falling/Slack with its arrow), not just height and time, since it's the only
on-screen readout while the grid is scrolled out of view.
