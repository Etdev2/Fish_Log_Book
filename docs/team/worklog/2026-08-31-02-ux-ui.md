### 2026-08-31 | ux-ui | Tackle Box MVP

- Saved the founder's spec at `docs/specs/tackle-box.md` and built the MVP against it.
- **Flagged one architecture conflict rather than deciding it** (§37 asks for exactly this):
  the spec organises gear by Category — including rods, reels, line and tools — but the
  database's `tackle_item` requires a `lure_class_id`, and a rod has no lure class. Wrote it
  up for `architect` in `docs/team/channel/2026-08-31-01-ux-ui-to-architect.md` with the
  option I think is right and why. Nothing in this pass touches `supabase/migrations/`.
- What the screen does now: browse fifteen gear categories with live counts; search across
  name, brand, size, colour, weight, notes, tags and the category's own word; filter by
  category, brand, favourites and low stock; sort six ways; add an item with just category,
  name and quantity; edit, duplicate and delete it; change quantity with − / + without
  opening a form; mark favourites; attach a photo.
- The two entry-speed features the spec cares most about are in: **Duplicate** carries every
  field across so entering the next hook size is one field, and the form pre-fills the brand
  the angler last used and offers their recent brands, sizes and colours as one-tap chips.
- Delete is a two-step confirm and sits apart from the controls that get used constantly.
- Built for size: the list renders a window that grows as you scroll, rows that scroll off
  screen cost nothing to lay out, and a test searches a generated 5,000-item inventory and
  fails if it takes more than 100ms. It takes about one.
- Reused rather than re-made: the tide screen's bottom sheet moved to
  `src/components/bottom-sheet.tsx` and both features now use the same one, and the two
  alignment lines are now app-wide variables in `globals.css` rather than tide-only.
- Checked in a browser at 390x844: no page scrolling, search narrows live, the detail and
  add sheets open and close, adding an item works end to end, no console errors.
- Not done, and deliberately: no migration (see above); no nav entry for the tackle box (it
  is still reached from Settings); the 5,000-item case is proven in the logic tests but I
  have not driven the rendered list at that size in a browser.
- Files: docs/specs/tackle-box.md, src/features/tackle/**, src/components/bottom-sheet.tsx,
  src/styles/{sheet,tackle-box}.css, src/features/shell/components/shell-frame.tsx.
