### 2026-09-02 | head-dev (spec by coo) | ~2h

- The tide screen's data was going to run out on Thursday. It now fetches real predictions
  from NOAA instead of reading the copy that was pasted into the code a week ago.
- It keeps the last good fetch on the phone, so the tide screen still works out on the water
  with no signal. That was the whole point — this app is meant to be used where there is no
  bar of reception.
- What it does, in order, every time you open the screen: use the saved copy if it is recent
  enough; otherwise fetch fresh from NOAA and save it; if the fetch fails, use the saved copy
  even if it is old; if there is no saved copy at all, use the pasted-in data but only while
  it still covers today; and if none of that is possible, say plainly that no tide data is
  loaded rather than drawing a wrong chart.
- The screen now tells you which of those you are looking at — live, saved, or the built-in
  copy — instead of always claiming it was real NOAA data. Same rule as the backup badge: do
  not tell the angler something the code cannot actually check.
- Kept the pasted-in data instead of deleting it, which is what an earlier note said to do.
  It is now the last resort when someone opens the app offline for the first time. It turns
  itself off after Thursday rather than showing tides that are quietly wrong.
- The fetch goes through the app's own small server address rather than the phone talking to
  NOAA directly, because nobody could check whether NOAA allows that, and shipping a
  guess into the one screen that has to work offline is a bad trade.
- Two things added on review before this went in: a ten-second limit on the NOAA call, so a
  slow NOAA cannot hang the page instead of letting the offline copy take over, and a check
  that the requested station is actually a station number.
- 19 new tests, 412 to 431. They cover the merge of the hourly curve with the exact high and
  low points, the case where those two land on the same minute, a garbled reply, NOAA's habit
  of reporting errors while still saying "OK", when a saved copy counts as too old, and the
  cutoff date on the built-in data.
- Checked, not assumed: with NOAA unreachable the address returns a clean error in about a
  tenth of a second instead of hanging, a bad station number is refused, and the tide page
  still loads. `npm run verify` and `npm run build` both pass.
- Files: `src/app/api/tide/route.ts`, `src/features/conditions/queries/tide-wire.ts`,
  `tide-cache.ts`, `tide-series.ts` (+ three test files),
  `src/features/conditions/tide-screen.tsx`,
  `src/features/conditions/components/catch-tide-panel.tsx`, `station-details-sheet.tsx`
- Next, and honestly: **nobody has ever called the real NOAA address from here.** This
  machine is not allowed to reach it, so the shape of NOAA's reply is our best understanding
  and not a checked fact. It is written down in one file so it is a one-place fix if it is
  wrong. The owner can settle it in a minute by opening the tide screen once it is deployed.
