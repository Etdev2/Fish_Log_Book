### 2026-09-01 | ux-ui | Quick Mark becomes an opt-in accelerator

Founder revision on the Fish Log: the quick mark should not be the biggest control in the
app by default. Full write-up in `docs/design/09-fish-log.md` (second slice).

- **Off by default, behind Settings → Fishing shortcuts.** The preference is stored on
  the device and survives reload. The underlying D22 behaviour is untouched — offline
  write, no GPS wait, no network wait, unresolved row — only whether the control is on
  screen.
- **The header collapsed** from an 88px control bar to a 47px status line carrying just
  the backup badge. No hole left where the button was.
- **The bottom placement is not a new idea.** `05-app-shell.md` §1 already says the
  shell's primary action is "docked at the bottom… this is where the quick mark lives".
  The first slice's header placement contradicted that. This makes the code agree with
  the document rather than inventing a third position.
- **The conflict I did not resolve silently.** The revision asks for something compact;
  `03-touch-and-interaction.md` §1/§5 sizes this control at 88px precisely because it is
  meant to be used by feel, not by sight. I kept 88px and flagged it — shrinking it to
  look tidier would break the one property it exists for. It is 110×88 in the corner,
  ~3% of the screen, and off by default.
- **Undo in the toast**, which §5 of that same doc specifies and the first slice missed.
- **One preference system, not two.** `preference.ts` now holds the localStorage +
  ref-gated `useSyncExternalStore` mechanics `units.ts` had worked out, and both go
  through it. Migrating `units.ts` was the real regression risk here, so the tide
  screen's unit switching got its own 11 checks.
- **A bug the screenshots caught and the assertions did not.** `sticky bottom-0` pins to
  the viewport bottom — where the nav is — so the button sat on top of the Settings tab.
  A bounding-box assertion passed because it measured a scroll position where they
  happened not to overlap. It now hangs at `bottom-full` off a shared bottom dock (the
  nav's own top edge, no hardcoded height), and there is a check that hit-tests every
  nav tab rather than trusting its rectangle.
- **Tide is untouched**, deliberately. Every quick-mark placement that fits there either
  covers the timeline being scrubbed or breaks the date bar's centred symmetry, and this
  revision was told not to redesign Tide.
- Checks: `npm run verify` green (281 tests) + `npm run build` green; 37 browser checks
  at 390×844 with zero console errors, plus 11 on the units preference. Catch logging
  re-measured at 193 ms. Not tested on a real phone.
