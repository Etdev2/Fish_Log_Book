### 2026-08-29 | head-dev | 90m

- Built the tide half of ADR 006: pure maths in `src/core/`, no React, no `Date.now()`
  inside any calculation — the present moment is always a parameter.
- Branded SI scalars (`Instant`, `Metres`, `MetresPerHour`, `Knots`, `Degrees`) and
  `Sourced<T>` for provenance. On purpose there is no conversion between a tide-height
  rate and a current speed — the founder was explicit that mixing those up would be a
  real bug, not a nice-to-have separation.
- The height curve now uses a shape-preserving monotone cubic instead of straight lines
  between hourly points, so it stops flattening the peaks without ever inventing a water
  level higher than a published high or lower than a published low.
- Slack water is estimated as a window around each high/low, not read off the turn
  itself — high/low water and slack current are different things, and this app has no
  current-measuring station nearby, so every slack value comes back marked "estimated"
  with a plain-English explanation, never "published".
- Mid-task, the founder changed how "is this tide moving fast" gets classified — from a
  ratio against a rough baseline to a percentile against the whole loaded time window,
  with five bands instead of three. Rebuilt that piece to match; it's now the last
  commit in the pace group, on top of a still-useful `ratio` number kept for later.
- Added the one hook that's allowed to read the real clock (`useNow`), built so it
  can't cause a mismatch between what the server and the browser first render.
- Added an ESLint rule that blocks reading `.value` straight off an estimated value
  under `features/**` — it understands the difference between an actual estimated
  value and an unrelated `.value` (like a form input), which a simple text-matching
  rule could not have done without constantly crying wolf.
- Files: `src/core/units.ts`, `src/core/ontology/timeline.ts`,
  `src/core/rules/tide/**`, `src/lib/time/use-now.ts`, `eslint.config.mjs`.

  tests.
- Next: nobody has wired this into the actual chart yet — that's the view lane's job

  three-day fixture window that's currently loaded; it will read differently once a

### 2026-08-29 | head-dev | +25m (review follow-up)
- Code review came back with three findings on the tide engine. All three are fixed:
  1. `PaceBaseline` was reporting the wrong count (leg count instead of the actual
     distribution size the percentile is ranked against) — a genuinely misleading
     number, not just a naming issue. Fixed, and split into separate `sampleCount`
     (distribution size), `sampleInterval`, and `legCount` fields. `PACE_BANDS` (the
     percentile cut points) is now exported and public.
  2. The `.value` lint rule now also catches destructuring
     (`const { value } = reading.rate`) and literal computed access
     (`reading.rate["value"]`), not just plain dot access. Verified against five real
     violation shapes and two negative controls (a DOM input, and a genuinely dynamic
     computed key, which cannot be caught and is documented as such in the rule).
  3. Added tests for `nextSlackAfter` that would fail if it regressed to a fixed
     bracket around a turn: the window narrows when `slackBelow` shrinks, and a sharp
     synthetic turn gets a measurably narrower window than a gentle one.
- `npm run verify` passes, 45 tests.
- Heads up for the view lane, which branched off before this fix: `PaceBaseline`
  gained fields, and the *value* behind `sampleCount` changed meaning (it now
  correctly describes the distribution, not the leg count) — not a type break, but
  worth a rebase rather than a silent merge if anything already reads that field.
