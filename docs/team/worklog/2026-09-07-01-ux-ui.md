### 2026-09-07 | ux-ui | 3h

Tournament redesign, part one of three: finding an event. The founder's complaint was that
the section is confusing, and the specific ask was an event calendar with a calendar view
and a list view showing location, current prize pool and when registration closes, plus a
"my tournaments" page.

- **The old hub was a diagram of the product, not a view of the season.** It sorted events
  into three fixed sections with a four-step explainer on top, and you could not tell where
  an event was, what it paid, or how long you had to enter without opening each one. Worse,
  an event moved between sections as its status changed, so nothing stayed where you last
  saw it. Replaced with one list of events, two views over it, and three filters.
- **Every card now answers the three questions you decide from**: where it is, what the pot
  is at, and how long you have. Plus the entry fee, how many are already in, and a badge if
  you are entered or hosting.
- **Calendar view** shares the month grid with the fishing calendar, so a September here
  lines up cell for cell with a September there. That maths moved down into `core/` — it
  now has two callers, which is exactly when the architecture doc says to move it.
- **My tournaments** is a real page now, at /tournaments/mine, and it leads with the count,
  which is what was asked for. Entered and hosting are counted separately: running an event
  you are not fishing is still a Saturday gone.
- **Found a real bug while planning.** The tournament migrations cannot be applied to an
  empty database: `public_tournament` selects `description`, `registration_opens_at` and
  `registration_closes_at`, and the tournament table has never had any of them. Added those
  columns (plus location, entry fee and currency) in the migration that creates the table,
  because a later repair migration would still sort after the view that needs it. Two more
  tables are referenced and never created — `tournament_division` and
  `tournament_award_category`. Those are the jackpot concept, so they belong to part two.

Checked: `npm run verify` clean (8 lint warnings, all pre-existing in files I did not
touch), `npm run build` clean, /tournaments and /tournaments/mine both still prerender.
Looked at it in a browser at 390px against the production build — list, calendar, tapping a
day, each filter, and the empty states — no console errors.
