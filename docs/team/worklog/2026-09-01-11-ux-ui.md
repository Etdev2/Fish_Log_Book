### 2026-09-01 | ux-ui | "+ Add catch for this day", the When row, Catch Detail, tide on the record

Founder Historical Catch spec (Track A), the screens.

- **Backfill door (§1).** Every day page — and every empty day — now leads with
  "+ Add catch for this day", deep-linking `/log?add=YYYY-MM-DD`. The Fish Log parses it
  once in a state initializer (SSR and first client render read the same URL, so no
  flash and no effect-cascade); the sheet opens titled "Log a past catch" and pre-set to
  **midday on that day** — never midnight-by-accident.
- **The When row costs nothing until touched.** Always visible, `datetime-local`,
  defaults to now (or the backfill day). It is *not* a required decision between the
  angler and Save — but a timestamp in the future switches Save off with an amber rail,
  because logging a fish from next Tuesday is how lying data starts. `useNow` is the
  only wall-clock allowed to answer that question (ADR 006 §7).
- **Conditions at the catch (§2)** sits inside Add details as a bordered fieldset:
  water temp, air pressure, wind speed (knots — both unit systems), wind-from as a
  16-point compass select. Placeholders calm the units ("64", "29.92"). Everything is
  optional; everything typed is the angler's own observation and the record says so.
- **Catch Detail (§3)** — `/catch/[id]` is the record, not a glance: hero (species, time,
  measured/estimated flags, notes as a pull quote, tags as chips), Where (spot, GPS with
  real accuracy or absent), Gear (role words + the standing-rig inheritance note),
  How it happened (outcome, disposition, presentation, current), Conditions section
  (angler-entered env + computed sun/moon), and actions — Edit reuses the same sheet as
  the Fish Log through the same `updateCatchFromDraft` path, Edit never re-fixes the
  GPS, delete keeps the sheet's two-step inline confirm. Day rows link "Open record →";
  unknown ids get an honest "No such catch", not a 404, because the record may simply
  not be synced here.
- **Tide panel (§6) has exactly three states and no fourth:** captured (rendered as
  stored, never recomputed — with the ±3h curve as an inline sparkline, dashed line on
  the catch), fill-now (moment inside the cached window: computed once, written back,
  next visit is state one), pending (outside the window: words, no numbers, nothing
  estimated from a neighbouring day). Freshwater renders nothing at all — on a lake
  "no tide" is geography, not a gap.
- Tooth-brush detail: "Wind (knots)" not "Wind speed"; the capture_mode badge reads
  "Backfilled record" / "Logged live" in words, not jargon; the tide pending copy says
  *why* ("outside the tide window cached on this device") instead of shrugging.
