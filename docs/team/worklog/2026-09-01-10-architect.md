### 2026-09-01 | architect | Historical catch: backfill truth, env columns in use, tide fill in core

Founder Historical Catch spec (Track A), data layer.

- **Backfill is row-level honesty, not a UI flag.** `captureModeFor(caughtAt, now, zone)`
  is the single pure decision: same local day ⇒ `live`, else `backfill`. Days compare in
  the *angler's* zone — 23:55 PDT typed at 00:00 PDT is a backfill, which the day-boundary
  test pins (five wall-minutes apart, different day). `logCatch` used to hardcode
  `"live"`; it now asks that question, and `snapshot_basis` follows automatically via the
  D24 wiring (`historical_reconstruction` downstream).
- **Manual environment (§2): schema already had the columns** — `water_temp_c`,
  `pressure_hpa`, `wind_speed_ms`, `wind_dir_deg` sit on `condition_snapshot` since the
  core migration. What was missing was plumbing: `SnapshotInput.manualEnvironment`, the
  four record fields, and a provenance line naming the source ("entered by the angler at
  log time") so analytics never mistakes a typed-in barometer reading for an instrument.
  Anglers type °F/inHg/kt (knots in both unit systems — marine convention); storage is
  canonical SI via new measurement converters (temp, pressure, wind) with a 16-point
  `compassLabel`.
- **Edit path is the save path's inverse.** `draftFromRecord(record, gear, snapshotEnv?)`
  reconstitutes the draft field-by-field (photos: `[]`, spec §10 re-attach is explicit);
  `updateCatchFromDraft` rewrites draft fields with `isNew:false`, preserving id, trip,
  created timestamps, lat/lng and capture_mode, and patches the snapshot's env columns
  only when the draft carries at least one value — an edit that never opened the
  Conditions block cannot blank it. Seeding flows both callers through the snapshot so an
  untouched block round-trips and a cleared field truly clears.
- **Tide fill (§6) lives in `core/rules/tide/catch-fill.ts`** after the ADR 006 §5
  tripwire refused `.value` unwrapping in features: `catchTideFillAt(series, atMs)`
  returns plain stored numbers — height, signed rate, state (flood/ebb/slack with the
  engine's NEAR_SLACK_BELOW band folded into slack), cycle %, twelfths hour, day range,
  and a ±3h 15-minute curve clipped at the series' ends rather than extrapolated.
  `null` when out of window; `null` is the pending answer, not an error.
- **One additive migration** (`20260901220000`): `tide_curve jsonb` + a shape check
  (array, ≤41 points — a bounded sample set, not a warehouse). The six scalar tide
  columns already existed. The seed vocabulary migration stays untouched, per the
  standing rule.
- **Feature direction stays one-way.** `LogSnapshot.snapshots` loads
  `condition_snapshot` rows so UI can read them; the tide panel (conditions feature)
  writes fills through `saveConditionSnapshot`. Catches never imports conditions —
  `/catch/[id]` composes the two features at the route, which is what a route is for.
- Tests 332→355: env converters round-trip (64.3°F, 1013.25 hPa↔29.92 inHg, 8 kt),
  compass wraparounds, `captureModeFor` boundaries, `draftFromRecord` round-trips and
  env seeding, tide fill flood/ebb/slack/pending/clipped-curve (fixture-like series,
  day range 1.277−0.296).
