Built the ADR 005 unblock list — the design system and the app shell. Branch
`head-dev/shell-and-tokens`. No product screens, per that ADR's own scope note.

- **Token pipeline (ADR 005 §2).** `src/core/design/tokens.json` is now in place —
  ux-ui's `docs/design/tokens.json` copied verbatim, values untouched, because they own
  those. `scripts/tokens.mjs` generates `src/app/tokens.generated.css` as a Tailwind v4
  `@theme` block; `npm run tokens:check` is the CI drift check and fails on a
  hand-edited or stale generated file. Wired into both `dev` and `build` so it cannot
  go quietly stale. A component now writes `bg-surface`, `text-h1`, `p-4`,
  `min-h-touch-primary-quick-mark` and imports nothing.

  `(internal)` for the team prototype. `/` is the month calendar route. `/learn` moved
  to `(internal)/learn` unchanged. The old Supabase connection check that was `/` is now
  a diagnostics block at the bottom of `/settings`, as the ADR specified.

  and holds the auth gate.
- **`src/features/shell/`** — nav (bottom-anchored for one-handed use; position is

  free of product chrome.
- **Tripwires, which is what makes the ADRs real rather than aspirational.** ESLint now
  enforces ADR 003 §6: `src/core/**` cannot import React, Next, or anything above it;
  `src/app/**` and `**/components/**` cannot import `@supabase/*`, with the ADR 005 §5
  allowlist and nothing else. `scripts/check-tripwires.mjs` fails on any new
  `*.module.css`, on any raw hex/rgb/px literal in a `.tsx`, and on a file in
  `core/rules/` with no test vector. `npm run verify` runs the lot.
- **Test runner picked: Vitest** (ADR 005 §6 left it open). Same TS/ESM the app already
  uses, no transform layer, plain Node for `src/core/` which has no DOM by law, and JSON
  vectors load as a plain import when ADR 003 §4's rule arrives. 8 tests: the type-scale
  floor, the touch-target floor, and ADR 004 §6's backup vocabulary, which is a contract
  and so is tested like one.

**Two things I changed my mind about mid-task, both worth knowing:**

- I hand-derived a `tokens.json` from `docs/design/01-foundations.md` before noticing
  ux-ui had already written the real one in `docs/design/`. Threw mine away and took
  theirs. Mine was missing the `focus-ring` colour and had invented a single 48px touch
  target where ux-ui had already set 48/68/88.
- I put the auth gate in `(app)/layout.tsx`, where ADR 005 §5 says to put it, and the
  build immediately showed every product route as dynamic — because a cookie read in a
  layout makes everything below it dynamic, which the same ADR forbids for exactly the
  right reason. Moved the gate into `src/proxy.ts`, which runs before render and
  redirects without costing the route its prerender. `/`, `/settings`, `/spots` and
  `/sign-in` are static again. Flagged to `architect` in the channel.
